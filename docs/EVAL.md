# 评测报告（可复现）

> 目的：把「感觉还行」换成可量化的数字。所有数字都能用一条命令复现：
>
> ```powershell
> mcte.exe --eval tools\eval_cases.tsv
> ```

## 1. 评测集

`tools/eval_cases.tsv`，一行一条，三种模式：

| 模式 | 含义 | 判分 |
|---|---|---|
| `segment` | 长串拼音 → 拆解/组句 | **top-1** 命中即通过，同时统计 top-3 |
| `en2zh` | 英文 → 中文反查 | 期望词出现在 **top-3**；top-1 单独统计 |
| `zh2en` | 拼音 → 中文候选 → 该候选的英文子项 | 中文在 top-3 且英文子项包含期望词；top-1 单独统计 |

多答案用 `~` 分隔（例如 `answer 回答~答案`），避免把「同义但对」判成错。

规模：**232 条**（segment 42 / en2zh 127 / zh2en 63）。

## 2. 结果（1.0.0，本机实测）

```
用例数: 232
top-1 命中: 222/232 = 95.7%
top-3 命中: 231/232 = 99.6%
```

**去掉人工校正表后的独立结果**（防止「照着答案教」）：

```
用例数: 148
top-1 命中: 140/148 = 94.6%
top-3 命中: 147/148 = 99.3%
```

（`data/en_overrides.tsv` 有 68 条人工校正，覆盖 127 条 en2zh 用例里的 84 条；
上面第二组数字是把它整段剔掉后跑的，代表 CC-CEDICT 本身的水平。）

唯一未命中的用例：

| 输入 | 期望 | 实际 | 说明 |
|---|---|---|---|
| `xianzaiqidian` | 现在几点 | 现在起点 / 现在其点 / 先在起点 | 「起点」词频略高于「几点」，属于真歧义，没有上下文无法判定 |

## 3. 长串组句（本轮新增能力）

以前 `bukeyitihuan` 这类连续拼音一个候选都没有（词库没有整串）。现在用词频做代价的
Viterbi k-best 切分（`core/src/segment.rs`）：

```
bukeyitihuan          → 1 不可以替换   2 不可一替换 …
bukeyi                → 1 不可以       2 不可一 …
womenmingtiankaishi   → 1 我们明天开始 2 我们明天开是 …
xiexienile            → 1 谢谢你了     2 谢谢腻了 …
zhongguoren           → 1 中国人       2 中国人的
```

代价公式：`cost(word) = ln(rank + 1) + 8.5`，句子 = 各词代价之和；
加 `8.5` 是为了惩罚碎词（否则系统会偏好「不 / 可 / 以 / 替 / 换」这种全单字切分）。

## 4. 已知短板（诚实列出）

1. **没有上下文语言模型**：组句只靠词频，遇上「现在几(点|起)点」这种同频歧义会选错。
   要真正解决需要 n-gram 或小语言模型，属于下一阶段工作。
2. **人工校正表只有 68 条**：en2zh 的高频词靠它保底，生僻词完全依赖 CEDICT。
3. **中文→德/日/法/西** 仍只有 53 条手写词表（英文有 5.9 万词）。
4. 组句候选**没有译文子项**：像「不可以替换」这种拼出来的短语在 CEDICT 里没有整条释义，
   打开 AI（`ai.enabled`）时会由模型补。

## 5. 怎么扩展评测集

直接往 `tools/eval_cases.tsv` 追加行即可，格式见文件头注释。建议新增用例时：

- 每条都要能用 `mcte.exe --probe <输入>` 人工复核；
- 一张表只放「本来就该翻成这个」的词，别拿歧义当失败；
- 同义答案用 `~` 写全（`购买|buy~purchase`）。
